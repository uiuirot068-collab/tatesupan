- **縦罫線 / Vertical Rule** (recorded 2026-09-07, Human-approved roadmap entry, documentation only): a future typography feature providing a proper, explicit vertical-rule typesetting element for users who want a long continuous vertical line in prose/design, instead of forcing repeated dash characters ("―――", "――――", etc.). Distinct from punctuation dash handling (P3-O04) — a separate author action/notation, not an automatic reinterpretation of repeated dashes (repeated-dash source must never be silently converted; a user may genuinely intend repeated dash punctuation). **Human-approved initial spec:** (1) length specified by character count, mapped to the canonical body-character advance for the current document/line metric — never arbitrary CSS px; (2) one standard stroke width only in the initial version, no user-selectable thickness (thin/medium/bold/custom em/px all excluded initially); (3) black only — no color picker, no gray variants, no inherited arbitrary text color (TateSpun publication output is grayscale/monochrome); (4) must not push surrounding manuscript text outward — occupies its own canonical typesetting space per Core placement, but painted stroke width must never cause reflow; (5) must be modeled as ONE formal semantic/canonical unit (conceptually `VERTICAL_RULE` or the project's eventual equivalent name, not frozen yet) — never as N repeated dash glyphs. **Future ownership (not yet implemented):** Editor/notation creates the element; Normalizer recognizes explicit notation if used; Core owns position/length/canonical occupancy/source identity/page-column-line association; Preview Renderer paints one black rule inside canonical geometry; Publication Renderer reproduces the same semantic rule — Renderer must never derive rule length from DOM measurements, push neighboring text, or auto-convert repeated dashes. Must be reproducible identically by both Preview and Publication renderers from the same canonical model (never a browser-only CSS trick). Future Editor UX (not designed yet): an explicit "縦罫線" insertion action taking only a character-count length (`長さ: [ 5 ] 文字分`). Cross-referenced future checker rule: 文章チェックβ v2 may eventually add a separate NOTICE_ONLY suggestion (「長い線として使用する場合は、縦罫線機能も利用できます」) when 3+ consecutive U+2015 characters are detected, pointing the author at this feature — informational only, never auto-replacing/auto-converting/erroring. Non-goals for the initial version: user-selectable width, color/gray/dotted/double/decorative/gradient variants, horizontal rule, automatic repeated-dash conversion, arbitrary freehand or percentage-of-page length. Related to (but independently specified from) Dakuten Attachment above as a future expressive/special-typography item. **Not implemented. No numeric P3-O identifier assigned. Documentation only — no Core/Renderer/src/Production change made for this entry.**
