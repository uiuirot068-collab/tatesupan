# Core Module Map

- Status: **P3-L03: REVIEWED / FROZEN FOR IMPLEMENTATION (2026-09-06, Master v1.8 §28.2).** Core implementation: NOT STARTED. This document is the concrete module boundary a future P3-L04+ loop implements against.
- Location: all modules live under `typesetting-v2/core/` (see `P3_CORE_IMPLEMENTATION_PLAN.md` §4 for the isolation rationale). Paths below are relative to that root.
- Every module is pure TypeScript with **zero** dependency on DOM, Canvas, PDF libraries, React, UI state, SNS, cloud, or AI. This is checked structurally (no such import exists anywhere under `core/`), not just declared.

## Notes

- No module is named `typesettingEngine.ts` or equivalent — this map exists specifically to prevent that collapse.
- `semanticRuns/` deliberately appears twice in the "First Loop" column: its break-opportunity *rule* is cheap and ships with P3-L07 (same loop as the general opportunity derivation), but its *integration* into the line composer's capacity math waits for P3-L12 alongside TCY, keeping P3-L07 and P3-L09 scoped to TEXT-only composition first.
- `ruby/`, `tcy/`, `semanticRuns/`, `images/` are all "plug into the line composer" modules, not sub-dependencies of it — `compose/line.ts` depends on their output types, they do not depend on `compose/line.ts`. This keeps the dependency DAG acyclic (see `P3_CORE_IMPLEMENTATION_PLAN.md` §6).
- `measurement/facts.ts` is a contract (interface) module with no implementation; `measurement/fakeProvider.ts` is the only concrete provider until a real Renderer-adjacent measurement adapter is designed (out of Core scope, P3-O08/O09 territory).
