## Highest migration risks (summary)

1. **Capacity/margin derivation formulas** (chars-per-line, lines-per-column, margin↔capacity conversion) — history of real drift bugs (~1.5mm, and the 40×17→39×15 default fix) from multiple independent formula copies. v2 must centralize this.
2. **Export capture pipeline** (`capturePageToCanvas`, shared by PDF and JPG export) — deeply coupled to FixedSlot DOM internals via extensive documented workarounds; not portable as-is to any other renderer.
3. **Ruby rendering as manually-positioned annotation glyphs**, not native CSS `<ruby>` — a real visual-fidelity gap if v2 adopts a different shaping approach; needs an explicit accept/reproduce decision, not silent drift.
4. **Duplicated kinsoku/hanging/pagination logic** across `paginateTokensByLines` (page splitting) and `computePageSourceRanges` (caret↔page mapping) — two independently maintained mirrors of the same algorithm today; a real risk of the same duplication recurring in v2 if not deliberately designed against.
5. **TCY's fixed 1-character-cell pagination budget** regardless of glyph width — a simplification that may not survive a non-FixedSlot renderer unexamined.
6. **Manual-page-break soft-close/hard-break coincidence suppression** and **trailing-image-attaches-to-soft-closed-page** bookkeeping — both flagged by the researcher as intricate, plausible sources of off-by-one bugs if reimplemented differently.
7. **Cloud schema looseness** (`Project.settings: Record<string, any>`, string-matched Postgres error sentinel) — an existing API-design smell worth fixing rather than preserving.
