# TSP-SAFE-002 クラウドの食い違いを直す（②）

- 元: TSP-REVIEW-001 の 5章「直す順」の ②（3の4・3の5。3の2 は SAFE-001 で直し済み）。報告 `/mnt/project-files/TateSpun/review-001/REVIEW.md`。
- 基準: master c6298c4（SAFE-001 公開後）。
- データベースは変えていない（SQL なし）。本番の `projects_set_updated_at`（保存日時をデータベースの時計で入れる）をそのまま使う。

## 何が困っていたか

1. クラウドが読めないと（通信が切れた・ログインが切れた）、理由を問わず「クラウドで消された」とみなし、つながりを消して新しい作品として保存していた。クラウドに同じ作品が2冊でき、15冊の枠を食った。（3の5）
2. 「新しい版か」を確かめてから書きこむまでの間に別の端末が保存すると、黙って上書きしていた。データベース側の守りがなかった。クラウドが読めない時は確かめずに上書きしていた。（3の4）

## 直したこと

**読めない ≠ 消えた（`lookupProject`、`src/lib/supabase/projects.ts`）**
- 答えを3つに分けた: 見つかった／無い（ログインしていて、読めて、その作品が無い）／読めない（通信の失敗・ログイン切れ・その他のエラー）。
- 「無い」の時だけつながりを消して新しい作品として保存する。保存できたら「元の作品が見つからなかったため、新しい作品として保存しました」と知らせる。
- 「読めない」の時はつながりを残したまま保存をやめ、「クラウドに接続できなかったため、保存をやめました。書いた分はこの端末に残っています」と出す。ログイン切れならログインの案内を出す。

**上書きはデータベース側で版を確かめる（`updateProject` の第3引数）**
- 上書きは毎回「この保存日時の版を上書きする」と名指しし、データベースは行がまだその版の時だけ書く（`updated_at` が一致する時だけ更新）。
  - ふつうの保存: 直前に読んだクラウドの版。
  - 確認の窓で「上書き」を選んだ時: 窓に出ていた版。窓を見ている間に別の端末が保存していたら、上書きしない。
- 1行も書けなかったら成功と扱わない。もう一度読んで、
  - まだある（別の端末が先に保存した）→ 今のクラウド版で確認の窓をもう一度出す。
  - 無い（その間に消された）→ つながりを消し、「もう一度押すと新しい作品として保存します」と出す。
- 読む・書く時に「自分の作品だけ」の条件も足した（データベースの守りとの二重の守り）。

## 変えていないこと

- クラウドの作品を「保存作品一覧」から開く時の読めない／無いの区別（今までどおり「保存できません」の表示）。③の「読み込みの失敗からの復帰」で扱う。
- データベースの表・守り・トリガー。
