### 奥付の直しの中身

前は次のようになっていた。

- PDF・JPG: 奥付が2ページ以上になると、どのページにも奥付の全文をくり返して描き、紙の下へはみ出していた。
- ページ数: 奥付の文を本文と同じ縦書きで組んだ時のページ数を使っていた（横書きの奥付の本当の長さと関係なかった）。
- プレビュー: 奥付は1枚だけ表示し、「1ページに収まりきりません」と出していた。
- 自由欄だけの続きページで、先頭に 1.4 字ぶんの空き（テストの不合格 1 件）。

今は:

- 奥付の行を、配置の枠（余白の内側）の高さで区切ってページに分ける。行の途中では切らない。項目名と値は同じページに置く。
- 続きのページは、そのページの最初の行から上詰めで始まる。自由欄の上の空き（とクラシックの区切り線）は、同じページで上に項目がある時だけ。
- クラシックの枠は、ページごとにそのページの分だけを囲む。
- 1ページに収まる奥付は前とまったく同じ（同じ描き方の計画をそのまま使う）。
- ページ数（ノンブルや本文のページ順）は、奥付の本当のページ数に合わせる。合わない時だけ、組版エンジン（Core）には1ページ1行の仮の文を渡す。
- 「奥付ページ（JPG）」と「選んだページの PDF」は、奥付の全ページを出す。
- 不合格は 1 → 0（`ci/known-failures.json` は空）。

### プレビューの字の下が欠ける・傍点（2026-10-18 なつおの確かめから）

- 原因: Google Fonts から読む書体には縦書き用の寸法（vhea/vmtx）がない。ブラウザは縦書きの字を枠より少し下へずらして描き、字ごとの枠の「はみ出しを隠す」設定が字の下を切っていた。書き出しは書体ファイルの字形をそのまま描くので欠けなかった。
- 直し: プレビューの本文は、PDF が埋めこむのと同じ `/fonts/*.ttf` を別名（`TateSpun Preview …`）で読んで描く（`previewFontFaceCss`）。しっぽり明朝のファイルは組版の計算でもともと読んでいるので、増える読みこみは他の書体を選んだ時だけ。読みこみ中は Google Fonts の書体が代わりに出る。字の枠のはみ出しを隠す設定はやめた。
- 傍点: 1px ほどの小さな箱を丸くしてから拡大していたので、点が四角い固まりに見えた。100px の丸を transform で縮めて置く（なつおの PC 側の直しを取りこんだ）。字が下にずれなくなったので、点は字の横にくる。

### プレビューの字間がつまったり開いたりする（2026-10-18 なつおの確かめから）

- 原因: ブラウザは字の位置を画面の1画素単位にそろえて描く。1字の送りが 10.5 画素のような半端な値だと、字と字の間が 10・10・12・10・11… 画素とばらつき、「くっつく・離れる」に見えた。PDF・JPG は半端な位置のまま描くのでそろっている。
- 直し: 漢字とかなは、書体ファイルの字の形（輪郭）を SVG で、書き出しと同じ位置（字の枠の上端＋書体の縦書きの原点 0.88 字、行の中心に字幅で中央そろえ）に描く（`src/lib/v2Bridge/previewGlyphOutlines.ts`、`PreviewGlyphOutlines`）。行ごとに SVG を1つにし、字の形は文書に1つずつ置いて使い回す。句読点・かっこ・小さいかな・ー・英数字・縦中横・ルビは今までどおり文字として描く（書き出しに専用の決まりがあるもの）。
- 測った結果（この環境、同じ字を37字並べた行）: 字の中心どうしの間隔のばらつき（標準偏差）が 0.59 画素 → 0.19 画素。
- 書体ファイルを読むまでの間は、今までどおり文字として描く。

## くらべる確かめの使い方

開発サーバーを立ててから:

```
TATESPUN_E2E_BASE_URL=http://127.0.0.1:3000 TATESPUN_PARITY_OUT=出力フォルダ npm run test:e2e:print-parity
```

- Google Fonts に届かない環境では `TATESPUN_E2E_LOCAL_WEBFONTS=1` を足す（`public/fonts/` の書体を使う）。
- PDF を画像にするのに `pdftoppm`（poppler）が要る。
- 前の結果と比べる時は `-- --baseline 前の/report.json`。差が 2 ポイント以上ふえたページ、枚数が変わった場面で失敗にする。
- 差の数字（%）は「インクの量に対する、ずれたインクの量」。ページ全体を最大 1mm ほど動かして一番重なる位置で測り、その時のずれ（mm）も出す。同じ組版でも JPG と PDF で 10% 前後、プレビューと PDF で 15〜30% ある（字の太さ・ぼかし・画面の解像度の差）。書体がちがうと 10 ポイント前後ふえる。数字そのものより、前の回からの増え方を見る。

### 2026-10-17 の結果（この環境の開発サーバー）

| 場面 | 選んだ書体 | 直す前のプレビュー | 直した後のプレビュー | PDF | プレビュー↔PDF の差（直す前 → 後、最大） |
|---|---|---|---|---|---|
| 文庫・しっぽり明朝 | しっぽり明朝 | しっぽり明朝 | しっぽり明朝 | しっぽり明朝 | 30.2% → 30.2% |
| 文庫・Noto Sans | Noto Sans ゴシック | しっぽり明朝 | Noto Sans | Noto Sans | 35.9% → 22.0% |
| 文庫・Zen オールド明朝 | Zenオールド明朝 | しっぽり明朝 | Zen オールド明朝 | Zen オールド明朝 | 31.9% → 26.4% |
| A5 2段 | しっぽり明朝 | | | | 19.9% → 19.9% |

長い奥付（自由欄 40 行）は、奥付を直した後でプレビュー・JPG・PDF とも 4 ページ（本文 2・奥付 2）、同じ所で分かれる。

JPG↔PDF は Noto Sans で 26.1% → 13.1%（奥付ページなど、書体の指定のない文字がしっぽり明朝で描かれていた）。

## 気づいたが直していないこと

- プレビューと PDF で、本文が全体に 0.5〜1mm ほどずれている（3書体・A5 2段すべて）。一番大きい差は1ページ目（ルビ・傍点のある行）。Phase 4 後半の「飾りを V2 の描き方へ」で調べる。
- 奥付の行の折り返しは英数字を 0.56 字幅と見積もっている（TSP-IMPROVE-002 の記録のまま）。
- 奥付のページ分けは余白の枠の高さで決める。柱やノンブルが余白の内側に食いこむほど余白が小さい時は、PDF で最後の行が柱・ノンブルに近づくことがある（前から1ページの奥付でも同じ）。
