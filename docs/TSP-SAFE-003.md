# TSP-SAFE-003 読み込みの失敗と画面のエラーからの復帰（③）

- 元: TSP-REVIEW-001 の 5章「直す順」の ③（3の10、原稿を救い出す手段）。報告 `/mnt/project-files/TateSpun/review-001/REVIEW.md`。
- 基準: TSP-SAFE-002（107737a、未公開）の上。データベースは変えていない。

## 何が困っていたか

1. 作品を読み込む途中で失敗すると（ブラウザの保存場所が使えない・一部のプライベートモードなど）、「読み込み中」のまま止まっていた。
2. 保存作品一覧からクラウドの作品を開こうとして読めないと、「保存できません」と出るだけで、理由も次にすることも分からなかった（SAFE-002 の残り）。
3. 画面を描く途中でエラーが起きると、エラーを受けとめる画面（`error.tsx`）がなく、真っ白になることがあった。

## 直したこと

**読み込みの失敗（`TategakiEditor.tsx`、`src/lib/editorRescue.ts`）**
- 読み込みの失敗を受けとめ、理由を出す: このブラウザの保存場所が使えない／クラウドに接続できない／ログインが切れている／クラウドに見つからない／その他。
- 「もう一度読み込む」「本棚へ戻る」を出す。ログイン切れなら「ログイン」、この端末にその作品の控えがあれば「この端末の控えを開く」も出す。
- 失敗した時は画面を空にし、この画面では何も保存しない（前に開いていた作品の書きかけは、空にする前に保存しきる）。「この画面で書いた分は保存されません」と出し、閉じる時は確認が出る（SAFE-001 の仕組み）。

**画面のエラー（`src/app/editor/error.tsx`、`src/app/global-error.tsx`、`src/components/EditorCrashScreen.tsx`）**
- 白い画面のかわりに「画面にエラーが起きました」を出す。
- 画面が最後に表示していた原稿（題名・本文・作品のメモ）を、「TXTで保存」「コピー」「本棚に控えを残す」（「題名（救出した控え）」として新しい作品に）で取り出せる。
- 「もう一度開く」「本棚へ」。
- ボタン操作やあとから動く処理のエラーはこの画面では拾えない（Next.js の決まり）。保存と読み込みの処理は、それぞれ失敗を受けとめる形にしてある（保存は SAFE-001、読み込みは上）。

**Human QA 用（`npm run dev` のときだけ）**
- Ctrl+Shift+Alt+E で、わざと画面のエラーを起こせる。公開する版（ビルド）では何も起きない。
