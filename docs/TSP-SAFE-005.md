# TSP-SAFE-005 保存まわりの小さな残り（2026-10-19）

SAFE-004 の PC 側の点検で残った4つと、TSP-REVIEW-001 3章「小」のうち、このリポジトリのコードで直せるもの。

## 直したこと

- 壊れたリンク（/editor?id=abc）で、黙って空の作品を作らず「このリンクでは作品を開けませんでした」と出す。
- 本文の欠けた壊れた記録が1つあっても、本棚・ゴミ箱・エディタがエラー画面にならない（題名・本文が無ければ空として読む）。
- 画面エラーの救出画面: 保存されていない原稿があるとき「もう一度開く」の前に確認する（TXT・コピー・本棚に控えを取った後は聞かない）。「本棚に控えを残す」で挿絵と表紙の画像もいっしょに残す。
- 作品の番号: 同じ瞬間に2つ作っても、時計が戻っても、本棚にもゴミ箱にもない番号を使う（前は上書きされうる）。新しい番号の作品・控えには古いクラウドのつながりを残さない。完全に削除した作品のつながりも消す。
- 本をまとめる: 空いている番号で作り、本棚の札（bookshelfMetadata）も書き、60作品の上限を同じ手順の中で確かめる。短編集の印が書くと消える件は SAFE-001 で直っていた（writeDocumentRecord が印を残す）。
- ログイン: 英語のエラーを日本語に。新しく作るパスワードは8文字以上（今あるアカウントはそのままログインできる）。パスワード再設定も8文字以上。
- 守りのヘッダー（public/_headers）: nosniff・Referrer-Policy・Permissions-Policy（カメラ・マイク・位置情報を使わない）。 書き出しのとき out/_headers（いちばん上）へ移す（中に入ったままだと効かないため。scripts/build-basepath.mjs）。

## 直さなかったもの（理由）

- スクリプトの出どころを絞るヘッダー（CSP）と、ほかのサイトへの埋めこみ禁止: Supabase・字体・spuntales.net の画面と合わせて本番で確かめる必要がある。外すと画面が動かなくなるおそれがあるため、なつおの判断待ち。
- 期限切れ画像の削除まわりの細かい守り、ご意見送信の回数制限: Supabase のサーバー側（supabase/functions）で、まだ古い Supabase（rgv）で動いている。直すには本番のサーバーへの反映が要る。
- 公開先の住所が複数ある件（spuntales.net/tatespun/・tatespun.pages.dev・GitHub Pages）: どれを残すか、なつおの判断が要る。
