## 何が困っていたか

1. クラウドから開いた作品は、このブラウザに自動保存されなかった。表示は「下書き保存済み」のままだった。
2. 同じ作品を2つのタブで開くと、あとから保存した方が黙って勝った。消した作品も、もう片方の自動保存で生きかえった。
3. 自動保存に失敗しても、次に1文字打つまでやり直さなかった。

## 保存の作り（決めたこと）

端末控え・2つのタブ・やり直しは、同じ1つの仕組みで扱う（監査先の条件）。

**作品ごとの版番号（`DocumentRecord.revision`）**
- この端末の作品は、書きこむたびに版番号が1つ上がる。古い作品は 0 とみなす（データベースの形の変更なし）。
- 画面は、読んだ時の版番号を覚えておき、「まだその版のままのときだけ」書きこむ（`saveDocumentIfUnchanged`）。

**タブごとの保存の順番待ち（`src/lib/localSaveQueue.ts`）**
- 自動保存・Ctrl+S・画面を閉じる時の書きこみは、すべてここを通る。1つずつ順に書く。
- 作品ごとに「いちばん新しい書きかけ」だけを持つ。書きこみに失敗したら持ったまま、2秒・5秒・10秒・30秒（以後30秒ごと）でやり直す。その間に書き足したら新しい方に置きかわるので、古い原稿が新しい原稿の後に書かれることはない。
- 版番号が変わっていた（別のタブが先に保存した）ときは、上書きしない。この画面の書きかけを **別の作品「題名（書きかけの控え）」として本棚に残し**、この画面はその控えに切りかえて続ける。元の作品には別のタブの版が残る。両方残る（なつお 10/13 の補足）。
- 作品が無くなっていた（別のタブで消した）ときは、書きこまない（生きかえらない）。画面に「別の画面で削除されたため、ここで書いた分は保存されていません」と出し、「新しい作品として残す」を押せば新しい作品にできる。
- 保存できていない書きかけがあるままタブを閉じようとすると、ブラウザの確認が出る。

**クラウド作品の端末控え（`src/lib/cloudDeviceCopy.ts`、`openCloudDeviceCopy`）**
- クラウドの作品を開くと、この端末の本棚に同じ作品の控えを1つ作り、ふつうの作品と同じく自動保存する。2回目からは同じ控えを使う（開くたびに増やさない）。
- 控えは「最後にクラウドと一致した版」（クラウドの保存時刻と本文の指紋）を覚えている（`DocumentRecord.cloudSync`）。開くときに次のように決める。

| 控え | クラウド | 開いたとき |
|---|---|---|
| まだ無い | — | クラウド版から控えを作る |
| 未送信の書きかけなし | どちらでも | クラウド版に合わせる |
| 未送信の書きかけあり | 変わっていない | 控え（書きかけ）をそのまま開く |
| 未送信の書きかけあり | 変わった | 控えの書きかけを「題名（この端末の控え）」として別に残してから、クラウド版に合わせる |
| 一致した版の記録がない | 本文が違う | 同上（黙って上書きしない） |

- 「クラウドに保存」が成功したら、その版を「一致した版」として記録する。
- クラウドだけにあった挿絵も、この端末に保存する（本棚から開いても挿絵が出るように）。
- 控えを作れなかった時（ブラウザの保存場所が使えない等）は、これまでどおり画面だけで開き、表示は「この端末には保存していません」。

**保存の表示（端末とクラウドを分ける）**
- この端末: 「この端末に保存中…／保存済み／保存できません（やり直し中）／保存していません」。
- クラウドとつながっている時だけ、横に「クラウドにも保存済み」か「クラウドには未送信」。

## 変えていないこと（②以降）

- 「クラウド版の方が新しい」のうその確認（3の2）、通信の失敗と削除の区別（3の5）、データベース側の同時保存の守り（3の4）は ② で直す。
- 本棚で題名を変えた時は版番号を上げない（別のタブで開いている画面は、これまでどおり題名を上書きしうる）。
- 端末控えも本棚の60作品に数えるが、上限の確認は新しく作る時（本棚の「新しく書く」）だけで、これまでと同じ。
- クラウドの表・守り・つなぎ先には触れていない。
