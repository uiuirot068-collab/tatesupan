# CST-PORT-013 確認用PDF（COLUMNSTAND → TateSpun）

移植ロードマップ候補5（棚卸し B3）。表紙（CST-PORT-011）が前提。
元: columnstand `chatgpt/editor-v3-2-compact` 297c617 の書き出し画面「確認用PDF（表紙＋本文＋裏表紙）」。土台: TateSpun master dfb1582。

## 入口
- プレビューの「書き出し ▾」（スマホは共通の書き出しシート）→「確認用PDF（表紙＋本文＋裏表紙）」。
- 中身はふだんの「PDF出力」の画面を確認用として開いたもの。題名が「確認用PDF（表紙＋本文＋裏表紙）」に変わる。

## 中身
- 読む順に1つのPDF: 表紙 → 本文（目次・奥付を含む全ページ）→ 裏表紙。
- 表紙・裏表紙は「反映」を押した面だけ。未反映の面は飛ばして、画面に「（表紙は未反映）」のように出す（止めない。CST と同じ）。
- 背表紙はページとして入れない（CST と同じ）。
- 表紙は表紙の書き出しと同じ描画（coverPaint → coverCanvas、350dpi、端末の上限を超えるときだけ下げる）で JPG にし、カラーのまま入れる。本文はふだんの PDF と同じ（グレー、文字はベクター）。
- 対象はいつも全ページ（「選択ページ」は出さない）。
- 出力は「仕上がりサイズ」「断ち落としサイズ」の2つ。トンボ付きの入稿用（フル）は出さない。
- 保存名は `{名前}_proof.pdf`（CST と同じ）。
- 書き出し前チェック（画像リンク切れ・奇数ページ・4の倍数・低解像度）はふだんのPDFと同じ。ページ数は本文側（目次・奥付を含む）で数え、表紙・裏表紙は数えない（なつお 2026-10-03。CST は確認用PDFでは奇数ページの注意を出していなかった）。
- 「完成前チェックリスト」（完成前チェックで「PDF書き出し時にこのリストを表示する」を選んだときだけ出る確認）も、ふだんのPDFと同じく出す（なつお 2026-10-03）。

## 作り
- `src/lib/cover/coverProof.ts` … 約束（名前・説明・保存名・並び・ページの置き方）。テストあり。
- `src/lib/cover/coverProofRun.ts` … 反映済みの面を JPG にする（ブラウザ専用、押したときに読み込む）。
- V2（いまの本番）: 書き出し用ワーカーの PDF ジョブに `leadingPages` / `trailingPages`（描画命令のページ）を足した。表紙は仕上がりの大きさのページに、塗り足し込みの画像を3mm外へはみ出させて置く。仕上がりPDFでははみ出しが切れ、断ち落としPDFではちょうど塗り足しの枠に重なる。グレー変換は本文だけ。
- 旧方式（LEGACY、非常用）: `exportCustomPdf` に `coverPages` を足し、同じ置き方で表紙を前後に入れる。

## CST との違い（意図したもの）
- CST は表紙を本文と同じ画素密度で画像化していた。TateSpun の本文は文字がベクターなので、表紙は表紙の書き出しと同じ 350dpi。
- CST の「色（カラー／グレースケール風）」は TateSpun の PDF に無いので付けていない（本文はいつもグレー、表紙はカラー）。

## 既知の残課題
- 表紙画像はこの端末にあるものだけ使う（無いと「表紙の画像がこの端末に見つかりません」で止まる）。クラウド画像は候補22で。
- 旧方式（LEGACY）は本番で使っていないため、画面での確認はしていない（テストは V2 のみ）。

## テスト
- `src/lib/cover/coverProof.test.ts`（npm test）: 名前・保存名、反映した面だけ・並び、ページの大きさと画像の置き方、断ち落としで塗り足しの枠に重なること。
- `src/lib/v2Bridge/exportWorker.test.ts`（`npx vitest run --config src/lib/v2Bridge/vitest.config.ts`）: 表紙・裏表紙のページが本文の前後に入り、本文はふだんと同じバイト列、表紙はグレー変換しないこと。
