# TSP-SAFE-004 ゴミ箱と使っていない挿絵の整理（④）

- 元: TSP-REVIEW-001 の 5章「直す順」の ④（3の6・3の8・3の9）。報告 `/mnt/project-files/TateSpun/review-001/REVIEW.md`。
- 基準: TSP-SAFE-003（7142b01、未公開）の上。クラウドのデータベースは変えていない。このブラウザの保存場所（IndexedDB）に「ゴミ箱」の表を1つ足した（version 5、今までの作品はそのまま）。

## 何が困っていたか

1. 本棚の作品を消すと、戻せなかった（確認の窓だけ）。（3の8）
2. 作品を消しても、その挿絵はこのブラウザに残り続けた。ブラウザに「消さないで」と頼んでいなかった。（3の9）
3. クラウドの作品一覧は、データベースの守りだけに頼っていた。（3の6）

## 直したこと

**ゴミ箱（`src/lib/db.ts`、`src/lib/trash.ts`、`src/components/TrashModal.tsx`、本棚 `HomeV2Client.tsx`）**
- 本棚の「削除」は「ゴミ箱に移す」になった（作品メニューのボタン名も「ゴミ箱に移す」。TSP-SAFE-004 Human QA）。作品はまるごと（本文・メモ・設定・クラウドとのつながり・挿絵）ゴミ箱に残る。
- 消した直後は本棚に「〇〇をゴミ箱に移しました。元に戻す」と出る。
- 本棚の「この端末に保存されている作品」の横に「ゴミ箱 n」。開くと、作品ごとに「あと何日で消えます」「元に戻す」「完全に削除」（もう一度確かめる）。
- 30日たった作品は、本棚を開いたときに自動で消える。
- ゴミ箱は別の表なので、60作品の数・本をまとめる・別のタブの「削除された」の見分けは、これまでどおり「無い作品」として扱う。
- 元に戻したとき、消す前から開いたままだった別のタブが古い原稿で上書きしないよう、版番号を1つ上げる（そのタブの書きかけは SAFE-001 の仕組みで別の控えになる）。
- 使い方ガイドの見本はゴミ箱に入らない（これまでどおり消せない）。

**使っていない挿絵の整理**
- 作品を完全に削除したとき、その作品だけが使っていた挿絵を消す。
- 本棚を開いたとき、どの作品（ゴミ箱の作品も含む）にも出てこない挿絵のうち、7日より古いものを消す（入れたばかりの挿絵は、作品の保存が少し後になることがあるので消さない）。
- 「使っているか」は作品全体（本文・メモ・表紙などの設定）を文字で探して決める。迷うときは残す側に倒れる。
- エディタで挿絵を外したとき、ゴミ箱の作品が使っている挿絵は消さない。
- ブラウザに「この端末の作品を消さないで」と頼む（`navigator.storage.persist`）。Firefox は利用者に質問が出るので頼まない。

**クラウドの作品一覧（`getProjectsResult`）**
- 自分の作品だけを、こちらからも条件にして読む（二重の守り）。データベースの守りの SQL はすでに `docs/supabase/migrations/20260903000000_tatespun_into_spuntales.sql` に残っている（記録の宿題は済み）。

## 変えていないこと

- 挿絵を縮めて保存すること（容量を減らす）。
- 小の項目の残り（短編集の札、ご意見の回数制限、パスワードの長さ、守りのヘッダーなど）。「一覧から消したクラウド作品を開いたまま保存すると英語まじりのエラー」は SAFE-002 で直った。

## QA 役10人の点検を受けての直し（10/18）

10人とも同じ範囲・同じ項目で点検した結果（/mnt/project-files/TateSpun/tsp-safe-004/qa10/REPORT.md）に出たものを、軽いものも含めて全部直した。

**重いもの**
- 本棚の最後の1冊をゴミ箱に移すと、「元に戻す」と「ゴミ箱」が出なくなっていた → 本棚が空の画面にも出す。
- 作品を開けなかった画面でも「クラウドに保存」が効き、題名なしの作品がクラウドに増えていた → 開けなかった画面からは保存しない（理由を出す）。

**中くらい**
- 開いたままの作品を別のタブで「完全に削除」すると、その画面の挿絵も消えていた → 「新しい作品として残す」で、その画面の挿絵を保存しなおしてから残す。
- クラウドに保存した作品を端末で完全に削除すると、挿絵も消えていた（クラウドの挿絵は72時間で切れる）→ クラウドに保存した作品の挿絵は、この端末に残す（ゴミ箱ができる前と同じ）。
- 「保存作品一覧」から開くとクラウドを読みなおさず、失敗の画面も出なかった（③-6）→ `?cloudId=` で開くのと同じ読み込みを通す。一覧が読めないときは「ありません」ではなく「読み込めませんでした」と出す。
- ゴミ箱から戻した作品が、開いたままのタブでは「削除された」のままだった → 「ゴミ箱から元に戻されました。この画面で書いた分は、まだ保存されていません」に変わる。削除の文も「ゴミ箱に移された／本棚のゴミ箱から元に戻せます」にした。
- 保存場所が使えないとき、本棚が「読み込み中」のまま → 理由を出す。
- 確認の窓を出しなおしたとき、理由がなかった → 「上書きしませんでした。この確認を見ているあいだに、別の端末で保存されました」と出す。確認のあいだにクラウドで消された作品は「見つかりません」の案内にする。

**軽いもの**
- ゴミ箱から戻すとき 60作品の上限を見ていなかった → 新しく作るときと同じく上限の案内を出す（クラウドに保存した作品は数えない）。エラー画面の「本棚に控えを残す」も同じ上限を見る（TXT とコピーはいつでも使える）。
- 字数に挿絵の記号まで数えていた → エディタと同じ数え方（ゴミ箱・エラー画面）。
- ゴミ箱を Esc で閉じられない → Esc で閉じる（確認中は確認だけを閉じる）。開くと「閉じる」にカーソルが入る。
- 暗い画面で赤い文字が読みにくい → 暗い画面用の赤にした。「30日」の前の余分な空き。
- 長い題名で「ゴミ箱に移しました」の行が崩れる → 題名だけを省略し、「元に戻す」は必ず見える。390px のゴミ箱で確認中も題名が読める幅を残す。
- 開けなかった画面で何も書いていないのに、ページを閉じるとき確認が出た → 書いたときだけ出す。
- 開けなかった画面で書いた分が「もう一度読み込む」「本棚へ戻る」で黙って消えた → 確認を出す。
- 保存場所の失敗のあと「もう一度読み込む」で直らなかった → ページごと読みなおす。
- 英語の「Failed to fetch」が出た → 「クラウドに接続できませんでした」の案内にする。
- 一部の挿絵が送れなかったときに「新しい作品として保存した」の説明がなかった → 両方の知らせに出す。
- ログインの期限切れ（Invalid Refresh Token）を「ログインが切れた」と扱っていなかった → 扱う。
- エディタ以外の画面のエラーで、古い原稿の控えが出ることがあった → エディタの画面のときだけ出す。
- ゴミ箱にある作品の古いリンクを開くと、黙って新しい空の作品になった → 「この作品はゴミ箱にあります」と出し、「本棚のゴミ箱を開く」で開く。
- 「本棚に控えを残す」を2回押すと控えが2つできた → 1つだけ。
- 本棚を開くたびに全部の挿絵を読んでいた → 使っていない挿絵の整理は1日1回だけ。
- 390px で失敗の知らせが上の段に少し重なった → 重ならない余白にした。

**確かめ**: `npm run test:all` 3824 合格・不合格 0。tsc は master と同じ LayoutProps だけ。lint は master と同じ既存の5件だけ（新しいものなし）。390px の画面でゴミ箱・空の本棚・ゴミ箱の作品を開いたときを実際に表示して確かめた。

## PC 側の10人の点検を受けての直し（10/19）

- 「どの作品も使っていない挿絵」を1日1回消す掃除をやめた。切り取った（Ctrl+X）挿絵や、別の端末で書いたクラウド作品の挿絵まで消していたため。挿絵を消すのは、クラウドにつながっていない作品を「完全に削除」したときだけ。
- クラウド作品の控えがゴミ箱にあるときにクラウドから開き直すと、ゴミ箱の控えを本棚に戻して使う（新しい控えを作らない）。別の控えがあるときに古い控えを戻すと、ふつうの作品として戻す（1つのクラウド作品に控えは1冊）。戻すときの新しい番号は本棚にもゴミ箱にもない番号にする。
- 作品を開いただけで保存し直していた（前からの不具合）。2つめのタブで開くと、1つめのタブの次の書きこみが「（書きかけの控え）」に分かれていた。開いたときから何も変わっていなければ書かない。
- ログインしていない人には「保存作品一覧」でエラーでなく案内を出し、クラウド作品を開けないときも「ログインしていないため」と言う。
- 開けなかった画面でエラー画面が出たら「まだ保存されていません」と言う。ゴミ箱の日数は30日を超えない。移せなかったときは「移しました」と言わない。
- 直さなかったもの: 奥付が2ページに分かれる件は組版（TSP-PRINT-001）の側なので、組版のスレッドに渡す。ゴミ箱から戻された作品を開いたままのタブが自分で保存を再開しないのは、戻した作品を上書きしないための作り。
